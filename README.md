Tradução Automática usando Atenção (RNNs)Este repositório contém a implementação do projeto de Tradução Automática baseado em Redes Neurais Recorrentes (RNNs) com Mecanismo de Atenção. O objetivo principal do modelo desenvolvido é receber datas escritas em formatos humanos variados (ex: 15 de março de 2005, October 23, 1998) e padronizá-las para o formato de linguagem de máquina "YYYY-MM-DD" através de uma arquitetura Encoder-Decoder bidirecional.O projeto explora a eficácia das RNNs (Bi-LSTM e LSTM) e do mecanismo de atenção em tarefas de tradução pontual e alinhamento de sequência para sequência.Estrutura do RepositórioO repositório está organizado de forma modular, separando scripts de código, conjuntos de dados, visualizações de métricas experimentais e pesos treinados da rede.📁 Raiz do Projeto.gitattributes e .gitignore: Arquivos de configuração de controle de versão do Git.  Model.ipynb: Notebook Jupyter interativo contendo a estrutura de modelagem, exploração de dados ou validações locais.  requirements.txt e requirements-mac.txt: Arquivos de texto listando as dependências do Python necessárias para executar o projeto em diferentes sistemas operacionais.  1epocas.weights.h5, 50epocas.weights.h5, pesos100epocas.weights.h5, pesos100epocasV2.weights.h5: Pesos da rede neural salvos em diferentes estágios de treinamento para análises comparativas e recriação de testes.  attention_map.png: Uma amostra visual geral do funcionamento do mecanismo de atenção.  📁 src/ (Código-Fonte)Este diretório concentra o código principal do projeto, construído em Python de forma modularizada:  int_to_string.py e string_to_int.py: Scripts utilitários responsáveis pelo mapeamento de conversão entre caracteres e seus respectivos índices numéricos nos vocabulários (vetorização).  load_dataset.py: Script para carregar as bases de dados e instanciar os tensores.  preprocess_data.py: Pipeline de processamento contendo funções para padding e one-hot encoding.  model.py: Arquivo central que define a arquitetura da rede neural (camadas de codificação, mecanismo de atenção e decodificação) utilizando Keras/TensorFlow.  plot_attention_map.py: Lógica de geração gráfica que extrai e plota a matriz de pesos de atenção $\alpha$ da rede gerada durante a decodificação.  train.py: Script contendo o laço de execução e os hiperparâmetros de compilação (otimizador Adam, learning rate, épocas, etc.) para o treinamento do modelo.  testeEpocas.py: Arquivo para avaliação programática do impacto temporal no aprendizado da rede através do treinamento com 1 e 50 épocas.  📁 src/teste_unidades/ (Testes Arquiteturais)Subdiretório com o aparato de experimentação que varia o dimensionamento oculto da rede:  criador_teste.py: Script utilizado em conjunto com a biblioteca externa para gerar sinteticamente 500 novos casos ruidosos de validação.  model.py e model_teste.py: Arquivos de modificação arquitetural para iterar sobre diferentes parâmetros dimensionais da rede.  teste_unidades.py: Automação responsável por avaliar diversas combinações de unidades de pré-ativação ($n_a$) e pós-ativação ($n_s$) e salvar os resultados.  📁 data/ (Conjuntos de Dados)Contém os objetos persistidos para o treinamento e inferência consistentes:  dataset.pkl: Base de dados principal (treinamento/validação) em formato pickle gerada após o pré-processamento.  human_vocab.pkl e machine_vocab.pkl: Dicionários contendo o mapeamento numérico das linguagens de origem e de destino.  inv_machine_vocab.pkl: Dicionário reverso utilizado na última etapa da inferência para converter a distribuição de probabilidades gerada de volta em texto legível.  test_dataset.csv: Conjunto isolado de testes e de dados não vistos pelo modelo durante o treinamento de origem para garantir a generalização e medir as acurácias.  📁 attentiom_maps/ (Análise Visual)Contém os gráficos e resumos das saídas extraídos do modelo para avaliação do componente de foco temporal:  Arquivos attention_map_naX_nsY.png: Mapas de atenção referentes às variações numéricas entre as unidades de \textit{Encoder} (ex: 4, 8, 16, 32, 64, 128) e \textit{Decoder} (ex: 4, 8, 16, 32, 64, 128, 256) atestando as capacidades ou deficiências na retenção de coesão.  resultados_precisao.txt: Tabela condensada e formatada demonstrando o comparativo de precisão dos caracteres e da sentença em geral nos cenários descritos nos testes.  📁 pesos_unidades/ e weights/Armazenam os \textit{checkpoints} dos modelos gerados nos experimentos de topologia:  O subdiretório pesos_unidades/ abriga os arquivos .weights.h5 referentes aos testes incrementais, assim como espelha os gráficos do mapa de atenção vinculados a essas topologias experimentais (ex: pesos_na4_ns4.weights.h5, pesos_na64_ns128.weights.h5).  A pasta weights/ guarda os pesos isolados e definitivos da arquitetura avaliada sob model.h5.
